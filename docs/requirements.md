# 要件定義

## 1. システム概要

### 1.1 目的

本システムは、毎月の請求書作成作の業を楽にすることです。
ペルソナは高齢者で、直感的に使える機能・UIとします。

### 1.2 想定ユーザー

- 高齢者
- デジタル機器に馴染みのない人

---

## 2. ユーザー・権限

- 請求書作成

---

## 3. 機能要件

### 3.1 請求書作成

請求者作成に必要な項目は以下

- 何月分の請求書か（年 / 月）
- 店名
- 患者（請求先）一覧
- 患者ごとの金額（複数の場合もある。）

請求書作成画面では入力作業を優先し、所属、患者ごとの合計金額、全患者の合計金額は表示しない。
これらの合計金額は印刷画面に表示する。
店名は年月の右側に表示し、Enterキーまたは別の箇所をクリックしたときに自動保存する。
ただし、日本語入力の変換確定に使用したEnterキーでは入力を終了しない。

#### 完成形

上記項目を入力して、最終的に完成系に必要な項目は以下

- 何月分の請求書か（年 / 月）
- 店名
- 患者（請求先）一覧
- 患者ごとの金額（複数の場合もある。その場合は、各患者の合計金額も表示）
- 全患者の合計金額

#### 患者（請求先）の設定

毎月、請求対象はほとんど同じなので、選択した年月より前にある最新の請求書から、
年を跨ぐ場合も店名と患者（請求先）一覧を引き継ぐ。
患者ごとの請求金額は引き継がず、毎回未入力の状態とする。

追加や削除ができる。

以下の情報から候補者を検索できる。

- 氏名
- 所属

毎月約50人程度を想定

---

### 3.2 請求書印刷

請求書作成画面の右下に「印刷」ボタンを配置する。

「印刷」ボタンをクリックすると、印刷する用のページが表示される。

印刷のフォーマットは PDF で、./print-format.pdf の形式に、各項目を入力したものとする。

サイズはA4縦とする。
上から埋めていくものとし、患者数が少ない場合には、下部を空白にする。
一方、患者数が多い場合は、複数枚となっても良い。

表示された画面をそのまま印刷できるものとする。
請求書作成画面で設定した店名を印刷する。

---

### 3.3 候補者一覧 ・ 登録

登録されている患者（請求先）となる候補者一覧画面。

本画面から新しい候補者を登録できる。

入力項目:

- 氏名（必須）
- 所属
- 備考

必須項目が入力されていない場合は登録できない。

登録成功後は患者一覧画面へ遷移する。

患者情報は削除せず、患者編集画面から表示・非表示を切り替えられる。
非表示にする前に確認ダイアログを表示する。
表示・非表示の切り替えに成功したら、患者一覧画面へ戻る。
非表示の患者も過去の請求書には残すが、新しい請求書への引き継ぎと患者追加候補からは除外する。

## 4. 画面要件

### 4.1 画面一覧

| 画面 | URL | 説明 |
|---|---|---|
| ホーム | `/invoice` | 請求書作成 |
| 印刷 | `/print` | 印刷できる形で請求書を表示 |
| その他 | `/others` | 各種設定など |
| 患者一覧 | `/patients` | 患者一覧・検索 |
| 患者登録 | `/patient/register` | 新規登録 |
| 患者編集 | `/patient/:id/edit` | 患者情報編集 |

ホーム画面は、請求書作成を行う画面であり、画面下部のタブ(BottomNav)で「請求書」「患者」「その他」を配置。
ホーム画面の右下に「印刷」ボタンを配置し、その左隣に「患者を追加」ボタンを配置する。
「患者を追加」ボタンを押すと、患者選択フォームを画面中央のポップアップで表示する。
印刷画面の形式は、"./print-format.pdf" を参照し、PDFとする。
表示した画面をそのまま印刷できるものとする。

「患者」タブから患者一覧・検索・登録・編集を行う。

「その他」画面には設定など配置する予定だが、現状は遷移先のみ作成し、中身は保留とする。

患者一覧画面では、名前、所属、備考が表示されるようにする。
見出しの右側にある「表示／非表示」ボタンで、表示中の患者と非表示の患者を切り替える。

## 5. 共通要件

### 5.1 利用方法

本アプリは、デプロイは行わず、ローカルホストによる起動のみで利用するものとする。
よって、ログイン機能は必要ない。

macOSでは`scripts/start-app.command`、Windowsでは`scripts/start-app.bat`をダブルクリックすると、
バックエンドとフロントエンドを起動して請求書作成画面をブラウザで開く。
停止時は、それぞれ`scripts/stop-app.command`または`scripts/stop-app.bat`を使用する。
macOSのバックエンドはconda環境`devenv`で実行する。
Windowsのフロントエンドは、PowerShellの実行ポリシーに影響されないよう`npm.cmd`で起動する。

### 5.2 エラー表示

入力エラーが発生した場合、
ユーザーが修正方法を理解できるメッセージを表示する。

### 5.3 データ保持

ユーザーが画面を再読み込みしても、
登録済みのデータが失われないこと。

## 6. 非機能要件

### 6.1 UI

- PCで問題なく利用できる
- 色は青をベースカラーとする

### 6.2 パフォーマンス

通常の利用において、
ユーザーが著しい待ち時間を感じないこと。

## 7. 対象外

現時点では以下は実装対象外とする。

- LINE連携
- 外部求人サービスとの連携
- AIによる候補者評価
- スマートフォンネイティブアプリ
